# ADR-001: Разделение Game и UI

## Контекст
Процедурный код смешивал игровую логику и ввод/вывод (print/input). Это затрудняло автоматическое тестирование: тесты требовали ручного ввода с клавиатуры.

## Решение
Выделен отдельный класс `UI`, отвечающий за ввод и вывод. `Game` принимает объект `UI` через конструктор (инъекция зависимостей).

## Рассмотренные альтернативы
1. **Глобальные функции input/print.** Проще, но невозможно изолировать логику в тестах.
2. **Наследование Game от UI.** Приводит к жесткой связности и нарушению принципа единственной ответственности.
3. **Инъекция через конструктор (выбрано).** Обеспечивает гибкость, тестируемость и соответствие DIP (Dependency Inversion Principle).

## Последствия
- [x] Логика и взаимодействие с пользователем тестируются через Mock без блокировки консоли.
- [x] Легко заменить терминальный интерфейс на графический (GUI) или сетевой.
- [!] Дополнительный уровень косвенности (необходимость передачи ссылки на UI).
