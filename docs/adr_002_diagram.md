# ADR 002: Архитектурные решения диаграммы классов

1. Есть ли у вас наследование? Если да — обоснуйте.
Нет, в базовой версии наследование не используется. Все четыре сущности (Game, Board, Player, UI) выполняют принципиально разные роли и не имеют общей природы «является чем-то» (is-a). Если в будущем мы захотим добавить бота, можно будет сделать базовый класс Player и отнаследовать от него HumanPlayer и BotPlayer.

2. Есть ли композиция? Что чем владеет?
Да, здесь есть композиция:
- Класс Game владеет объектом Board (игровое поле создается внутри игры и не существует отдельно от текущей партии).
- Класс Game владеет списком объектов Player (два игрока создаются при инициализации сессии игры).

3. Есть ли циклические зависимости? (А использует В, В использует А)
Нет, циклы исключены благодаря однонаправленным связям:
- Game обращается к Board, Player и UI.
- Классы Board, Player и UI полностью независимы: они ничего не знают о классе Game и не вызывают его методы.
- Класс UI также не зависит от Board: игра сама запрашивает матрицу у Board и передает её в UI в качестве обычного аргумента для отрисовки.
