# ADR 002: Переход на базовый GameObject, датаклассы и протоколы

## Статус
Принято

## В чем была проблема
В первом модуле `Board` и `Player` были написаны сами по себе. Получилось неудобно:
1. У объектов нет общей базы: методы обновления и отрисовки называются как попало.
2. В коде много захардкоженных цифр (размер 3 на 3, условия победы), менять настройки неудобно.
3. Логирование было сделано через обычные принты прямо внутри логики.

## Что сделали
1. **Базовый класс `GameObject`**:
   - Сделали абстрактным через `abc.ABC`. Теперь у каждого объекта есть нормальный `id`, имя и обязательные методы `update` и `draw`.
2. **Протоколы ролей (`Movable`, `Drawable`, `Collidable`)**:
   - Взяли `typing.Protocol`, чтобы не городить сложное наследование. Если объекту нужно двигаться — делаем метод move, и он уже считается Movable.
3. **Конфиги через `@dataclass(frozen=True)`**:
   - Вынесли размеры сетки, символы и историю в отдельные датаклассы. `frozen=True` поставили, чтобы случайно посреди матча не перезаписать настройки поля.
4. **Миксин для логов (`LoggingMixin`)**:
   - Вынесли методы вывода логов в миксин с пустым `__slots__`, чтобы не плодить лишнюю память.

## Итог
- Плюсы: код стал чище, архитектура понятная, добавлять новые штуки (например, бота или таймер) теперь в разы проще.
- Минусы: файлов стало больше, для простой игры 3х3 кажется небольшим оверхедом, но для закрепления ООП самое то.
